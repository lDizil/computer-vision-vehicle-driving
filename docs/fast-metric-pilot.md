# Fast Mini: метрические боксы, прогноз смещения и варианты движения

Шесть камер в каждом снимке кодируются одним батчем закреплённого DINOv2. Читаем текущий и предыдущий снимки. По калибровкам поднимаем карты признаков в три метрические плоскости; предыдущий снимок переводим через две ego-позы в систему координат текущего. Видимость означает только попадание опоры в оптику, не отсутствие перекрытия объекта. Замороженный энкодер не дообучаем.

Малая обучаемая голова предсказывает центр, размеры, ориентацию и скорость моторных транспортных средств. Следующая разметка того же объекта задаёт целевое смещение в **текущей** ego-системе. Наблюдаемая длительность шага берётся из разметки только для обучения и оценки. Вызов Fast получает два наблюдённых кадра, не будущие позы или боксы. Опорное время LiDAR — геометрический якорь; снимок доступен не ранее последней экспозиции, которая записана отдельно.

Планировщик строит несколько различающихся продольных пробных траекторий из прошлой средней скорости и ранжирует их на прогнозируемых боксах. Движение объектов на горизонте планов предполагается равномерным; на данных измеряем только следующий keyframe. Проверка пересечений дискретная; варианты не выдаются за безопасные. Утверждение «не пересёк предсказанные боксы» не равнозначно «можно ехать».

## Что проверяем

- Разбиение по поездкам, без общей записи или JPEG. Для финала оставляем Mini Val; на dev выбираем порог и фиксируем веса.
- Пары `vision` / `geometry_only`: архитектура, стартовые веса, параметры обучения и поддержка клеток одинаковые. Контроль убирает только признаки картинок, но оставляет координаты и покрытие.
- На финале сопоставляем прогнозы и доступные 2D-по-земле центры внутри 2 м один к одному. Отдельно считаем ошибки высоты, размеров и ориентации. Для совпавших объектов с разметкой на следующем ключевом кадре проверяем прогноз смещения против неподвижного предсказанного бокса.
- Пустой прогноз и отрицательные результаты не перекалибровываем на финальной группе. Публикуем два режима и числа по отдельным сценам.

## Воспроизведение

`scripts.prepare_fast_mini` подготавливает `inputs/` и отдельно `targets/` из ранее скачанного официального архива. Затем `scripts.run_fast_metric_trial` запускается в закреплённом `Dockerfile.alignment`, без сети:

1. `capture`: только `inputs/` и DINO; наборы train/dev/test сохраняются без меток.
2. `fit`: только признаки и train/dev targets. Записываем выбранные на dev пороги и SHA256 весов в safetensors.
3. `predict`: только признаки и сохранённые веса; записываем предсказанные боксы и варианты, до чтения тестовых целей. В этот момент вычисляем внешнюю квитанцию SHA256 файла.
4. `score`: сначала требуем совпадения сохранённых прогнозов с внешней квитанцией `--sealed-sha256`, затем читаем тестовые цели.

Это первый блок Fast, не реальная замена штатного NAVSIM-агента. Полосы, будущий RGB-кадр, VQA, Safety Veto, замкнутое управление и утверждение о 10 Гц сюда не входят.
