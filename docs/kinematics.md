# Кинематические проверки

`check_kinematics(trajectory, motion, limits)` проверяет дискретные оценки движения до выбора траектории. Все входы относятся к одной фиксированной ego-системе задней оси на `t_ref`: x вперёд, y влево. `EgoMotion` содержит измеренные компоненты скорости и ускорения в этой системе; их не заменяем нулём при отсутствии данных.

Лимиты задаём явно через `KinematicLimits`: шаг в секундах, скорость в м/с, модуль ускорения в м/с² и модуль jerk в м/с³. Лимит ускорения действует на 2D-норму, включая торможение и боковое движение. Универсальных «безопасных» значений по умолчанию нет.

## Расчёт

Пусть `h=dt`, `p0=(0,0)`, а `p1…pN` — будущие точки. Требуем минимум три будущие точки, чтобы получить оценку третьей производной.

```text
u_i = (p_i - p_(i-1)) / h              скорость, средняя по интервалу
A_i = (u_(i+1) - u_i) / h              разности соседних средних
J_i = (A_(i+1) - A_i) / h

A_start = 2 * (u_1 - v0) / h
J_start = 6 * (u_1 - v0 - a0*h/2) / h²
```

В начале используем интегральные остатки относительно измеренных `v0,a0`. Для равномерного ускорения `A_start=a0`, `J_start=0`; для кубического движения с постоянным jerk `J_start=J_i`. Так не получаем ложный всплеск jerk из-за склейки производных, оценённых в разные моменты.

Сравниваем с лимитами максимальные 2D-нормы:

- скорость: `u_i` и измеренная `v0`;
- ускорение: `A_i`, `A_start` и измеренная `a0`;
- jerk: `J_i` и `J_start`.

Порог включительный. Округление на границе допускаем через `math.isclose(rel_tol=1e-9, abs_tol=1e-9)`. Шаг должен совпадать с конфигурацией с `rel_tol=1e-12`, без неявного пересэмплирования.

## Результат и ограничения

`KinematicReport` содержит измеренные максимумы, `within_limits` и все обнаруженные нарушения `SPEED / ACCELERATION / JERK`. Для `TIME_GRID`, `INSUFFICIENT_POSES`, `NUMERIC_RANGE` расчёт не считается успешным, максимумы остаются `None`, а не подменяются нулём. Неверные типы аргументов и некорректная конфигурация отклоняются через `ValueError`. Shape и NaN/Inf в самой траектории отсекает её контракт до этой проверки.

Это оценки по сетке, а не гарантия непрерывной динамической допустимости. Средняя скорость может не показать мгновенный пик между точками; шум измеренного ускорения усиливается в начальной оценке jerk. Проверки heading/yaw, кривизны, дороги и препятствий сюда не входят. Успешный отчёт нельзя трактовать как разрешение на безопасное движение.

На очень мелкой сетке округление третьих разностей может отклонить даже корректный аналитический профиль. Такой отказ сохраняем как failure, а не трактуем как доказательство физической невозможности; перенос на высокочастотный контроллер требует отдельной настройки численной политики.

Проверка выше не генерирует fallback и не выбирает кандидата. Эти потребители реализованы отдельно в [fallback/selection](fallback.md); они используют тот же отчёт и одинаковую конфигурацию для всех сравниваемых вариантов агента.
