Мы сначала снимаем риски воспроизводимости и проверяем пользу slow-контура, затем инвестируем в обучение и общий encoder. Это предложение последовательности; код агента пока не реализуем.

## Этапы и точки принятия решения

### 0. Feasibility и воспроизводимость

Проверяем наличие FSDrive driving-весов и доступной slow-модели; базовые pretrained-веса не выдаём за обученный агент. Проверяем формат фактических аннотаций, лицензионные условия и доступ к GPU. Сохраняем upstream commit SHA, preprocessing, checkpoint ID и checksum, версии среды.

**Выход:** хотя бы один воспроизводимый driving baseline и определённый путь к slow-прототипу. Если весов/кода нет, согласовываем обучение или альтернативу, а не начинаем Bridge против вымышленного API. Упоминания локальных `reason2drive_model_v2.py` и `reason2drive_dataset.py` в тикетах требуют получить и проверить сами файлы.

### 1. NAVSIM sanity-check и baseline

Выполняем `MV-124`, затем [MV-118](https://goddev.youtrack.cloud/issue/MV-118). Фиксируем выбранную версию NAVSIM и camera rig. Адаптируем горизонт/оси/heading к `Trajectory`, учитываем перенос nuScenes → nuPlan. ConstantVelocity подтверждает работу evaluator, но не работоспособность FSDrive.

**Выход:** реальные исходные метрики и проверенный контракт агента. Никаких заявлений о real-time на основании частоты simulator controller.

### 2. Контракты и offline slow experiment

Уточняем требования [MV-117](https://goddev.youtrack.cloud/issue/MV-117), [MV-120](https://goddev.youtrack.cloud/issue/MV-120), [MV-121](https://goddev.youtrack.cloud/issue/MV-121), [MV-122](https://goddev.youtrack.cloud/issue/MV-122) по реальным upstream API. До кода согласовываем границы модулей из [архитектуры](architecture.md). Начинаем с доступной image-input VLM и структурированного veto, передавая ей сам набор траекторий, а не только IDs/hash. Воспроизведение неопубликованного Reason2Drive не обещаем.

До абляций фиксируем offline fallback `Trajectory` для veto единственного кандидата и способ учёта failure без исключения сцен. Во всех вариантах используем одинаковую fallback-политику. Кинематические проверки строим по доступному ego-state; геометрические — только после выбора реального источника карты/объектов. Ground truth evaluator не подаём агенту.

**Выход:** baseline / checks-only / slow-only / combined на одинаковых данных. Если slow не даёт измеримой пользы, не масштабируем обучение автоматически.

### 3. Временная корректность

В отдельном temporal harness проверяем stale/out-of-order/invalid/timeout/all-veto и влияние общей GPU. Измеряем долю применимых veto, p50/p95/p99 и пропуски deadlines. Параметры deadline и TTL выбираем по замерам, не наугад.

**Выход:** ответ на вопрос, успевает ли slow реально влиять на актуальное решение. Офлайн PDMS этого не подтверждает.

### 4. Shared features и обучение

После положительных результатов изучаем multi-view fusion, trainable Bridge и alignment. Полная 6-camera обработка с калибровкой, геометрией и переносом признаков — исследовательское расширение, а не простая замена tensor shape. Обучение Stage 1/Stage 2 проводим после подтверждения данных, доступного кода и вычислительного бюджета.

### 5. Closed-loop

Переходим к CARLA/Bench2Drive после этапа временной корректности. Фиксируем версии и маршрутный протокол. Для Docker → Windows host адресом не считаем автоматически `127.0.0.1`: проверяем реальную сеть контейнера и адрес хоста. Для Bench2Drive совместимость серверной платформы проверяем отдельно.

## Предлагаемый стек

| Область | Предложение |
|---|---|
| Язык и ML | Python, PyTorch; точные версии выбираем по совместимому upstream. |
| FSDrive | Официальный upstream сейчас описывает Python 3.10, PyTorch 2.5.1 и CUDA 12.4. Это расходится с образом PyTorch 2.1.2/CUDA 11.8 из MV-105; не закрепляем общий образ до проверки. |
| Slow | Методика Reason2Drive и доступная image-input VLM как baseline. Конкретную модель/веса выбираем после проверки лицензии и VRAM. |
| Обучение адаптеров | LoRA / alignment — после baseline; не считаем LoRA решением несовместимости vision features без данных. |
| Эксперименты | NAVSIM с закреплённым SHA; PDMS или EPDMS в зависимости от версии, без смешения результатов. |
| Поздний closed-loop | CARLA / Bench2Drive с совместимыми версиями, отдельно от ML-контейнера при необходимости. |
| Проверки собственного кода | pytest для преобразования координат, асинхронных контрактов, failure/degradation и выбора траектории. |
| Учёт результатов | YAML-конфиги, JSON/CSV-метрики, checkpoint IDs/checksums. Веса и датасеты держим вне Git. |

Источник версий FSDrive: [официальная установка](https://github.com/MIV-XJTU/FSDrive#%EF%B8%8F-installation). Предлагаемый стек пока не собран и не протестирован.

## Что нужно уточнить до GPU-запусков

- Какая NVIDIA GPU, объём VRAM, доступный диск и ОС runner?
- Где лежит уже подготовленный OpenScene Mini и как получить доступ к нему?
- Есть ли у команды код/веса Reason2Drive и FSDrive сверх публичного upstream?
- При отсутствии готовых весов допускаем ли обучение с нуля/дообучение, и каков бюджет?

Полные датасеты, веса и платные вычисления без отдельного согласования не загружаем и не запускаем.
